1. Основні об'єкти бази даних

1 Таблиця

Основний структурний елемент БД, що представляє сутність (наприклад, «Студенти», «Викладачі», «Предмети»).

Складається з рядків (записів) і стовпців (полів). Назва таблиці має відображати її зміст, наприклад Students.

2 Поле

Стовпець таблиці, який визначає атрибут сутності (наприклад, «Ім'я», «Прізвище», «Вік»).

Кожне поле має унікальну назву, тип даних (TEXT, INTEGER, DATE тощо) та додаткові властивості (обов'язковість заповнення, значення за замовчуванням).

3 Запис

Рядок таблиці, який містить конкретні дані про один екземпляр сутності.

Наприклад, у таблиці Students запис може містити дані: 1, «Іван», «Петров», 20.

Рис. Д.1. Структура таблиці: поля (стовпці) та записи (рядки)

2. Створення таблиць, означення полів і ключів

У LibreOffice Base таблиці можна створювати двома способами:

  • через графічний інтерфейс (режим «Створити таблицю в режимі дизайну» / «Майстер таблиць»);
  • за допомогою SQL-запитів (меню Засоби → SQL…).

2.1. Приклад створення таблиці «Students»

CREATE TABLE Students (
    ID        INTEGER PRIMARY KEY,
    FirstName VARCHAR(50) NOT NULL,
    LastName  VARCHAR(50) NOT NULL,
    Age       INTEGER
);

Варіант із автоматичним генеруванням значення первинного ключа (саме його використовує HSQLDB у LibreOffice Base):

CREATE TABLE "Students" (
    "ID"        INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    "FirstName" VARCHAR(50) NOT NULL,
    "LastName"  VARCHAR(50) NOT NULL,
    "Age"       INTEGER
);

2.2. Означення полів

Кожне поле має назву, тип даних та додаткові властивості. Наприклад:

  • ID INTEGER PRIMARY KEY — поле «ID» є первинним ключем;
  • FirstName VARCHAR(50) NOT NULL — поле «FirstName» має текстовий тип і є обов'язковим для заповнення.

2.3. Ключі

🔑 Первинний ключ (Primary Key)

Унікальний ідентифікатор запису. Наприклад, поле ID у таблиці Students. Не може бути порожнім і не може повторюватися.

🔗 Зовнішній ключ (Foreign Key)

Поле, яке посилається на первинний ключ іншої таблиці. Використовується для зв'язку таблиць та підтримки цілісності даних.

2.4. Приклад визначення зовнішнього ключа

CREATE TABLE "Grades" (
    "GradeID"   INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    "StudentID" INTEGER NOT NULL,
    "Grade"     VARCHAR(2),
    CONSTRAINT "FK_StudentID"
        FOREIGN KEY ("StudentID")
        REFERENCES "Students"("ID")
        ON DELETE CASCADE
        ON UPDATE CASCADE
);
Зверніть увагу! У наведеному вище прикладі таблиця Grades має складену структуру означення: спочатку перелічуються поля, потім — обмеження CONSTRAINT … FOREIGN KEY. Після останнього обмеження крапка з комою не ставиться, вона завершує всю інструкцію CREATE TABLE.

5. Підтримка обмежень цілісності в БД

Обмеження цілісності — це правила, які забезпечують коректність даних у базі. Наприклад, зовнішній ключ гарантує, що значення в одній таблиці відповідають значенням в іншій.

ОбмеженняЩо гарантуєПриклад
PRIMARY KEY унікальність та обов'язковість заповнення ID INTEGER PRIMARY KEY
FOREIGN KEY посилання на існуючий запис в іншій таблиці FOREIGN KEY (StudentID) REFERENCES Students(ID)
NOT NULL поле не може бути порожнім LastName VARCHAR(50) NOT NULL
UNIQUE значення не повторюється в межах таблиці Email VARCHAR(60) UNIQUE
CHECK перевірка значення за певними умовами CHECK (Age >= 6)
ON DELETE / ON UPDATE CASCADE автоматичне узгодження пов'язаних записів ON DELETE CASCADE
Практичний сенс Завдяки зовнішньому ключу неможливо додати оцінку студентові, якого не існує в таблиці Students. HSQLDB поверне помилку порушення цілісності — і це правильно, адже база даних залишається узгодженою.

6. Відображення моделі явища (сутності) структурою запису

  1. Сутність як таблиця. Кожна сутність (наприклад, «Студент») відображається у вигляді таблиці.
  2. Атрибути сутності як поля. Атрибути «Ім'я», «Прізвище», «Вік» стають полями таблиці.
  3. Запис як екземпляр сутності. Кожен запис у таблиці представляє конкретний екземпляр сутності (наприклад, студент «Іван Петров»).

8. Запити для перевірки цілісності бази даних

8.1. Перевірка зв'язку (INNER JOIN)

Показує, які оцінки отримав кожен студент. Записи без пари не виводяться.

SELECT
    s."FirstName",
    s."LastName",
    g."Grade"
FROM "Students" s
INNER JOIN "Grades" g ON s."ID" = g."StudentID"
ORDER BY s."LastName", g."Grade";

8.2. Кількість оцінок кожного студента (LEFT JOIN + GROUP BY)

SELECT
    s."FirstName",
    s."LastName",
    COUNT(g."GradeID") AS "Кількість оцінок"
FROM "Students" s
LEFT JOIN "Grades" g ON s."ID" = g."StudentID"
GROUP BY s."ID", s."FirstName", s."LastName";
Пояснення INNER JOIN повертає лише ті рядки, для яких існує відповідність в обох таблицях, а LEFT JOIN — усі рядки лівої таблиці (Students) навіть тоді, коли в Grades немає жодної оцінки (тоді COUNT дорівнює 0).

9. Питання для самоконтролю

  1. Що таке таблиця, поле та запис? Як вони співвідносяться між собою?
  2. Які типи даних підтримує HSQLDB? Наведіть приклади використання кожного з них.
  3. Чим відрізняється первинний ключ від зовнішнього?
  4. Які властивості може мати поле? Що означає NOT NULL та UNIQUE?
  5. Як модель «сутність-зв'язок» відображається на структуру реляційної бази даних?
  6. Які типи зв'язків існують між сутностями? Як реалізується зв'язок N:M?
  7. Що таке обмеження цілісності? Наведіть приклади.
  8. Для чого використовують ON DELETE CASCADE?
Показати короткі відповіді

1. Таблиця — сутність; поле — стовпець (атрибут); запис — рядок (екземпляр сутності).

3. Первинний ключ унікально ідентифікує запис у власній таблиці, зовнішній — посилається на первинний ключ іншої таблиці й реалізує зв'язок.

6. 1:1, 1:N та N:M. Зв'язок N:M реалізується через проміжну (зв'язкову) таблицю з двома зовнішніми ключами.

8. ON DELETE CASCADE автоматично видаляє пов'язані записи дочірньої таблиці при видаленні батьківського запису, зберігаючи цілісність даних.
